## C25 : import et sécurité (revue du 2026-10-09 · R5, R4, R3, R22)
`scenarios/C25.mjs` (tablette et téléphone, 7 vérifications) :
1. noms hostiles (`<img onerror>` dont le code survit à `toUpperCase()`, `"'><svg onload>`, `');…;//`) dans deux équipes enregistrées, leurs joueurs, un nom libre et le nom du match, à chaque écran (accueil, Nouveau match et alignements, message éclair, feuilles de joueurs, toutes les sections de stats, zones, fautes, fiches d'équipe, adversaires `libre:`, Historique, Classement, corbeille) : compteur `window.__x` à 0, aucun élément injecté, aucune erreur de page, texte restitué tel quel ;
2. identifiants hostiles injectés en mémoire (hors import) : chaque bouton rend à son gestionnaire (espionné) l'identifiant d'origine ;
3. import piégé (identifiants d'équipe, de joueur, de match, d'auteur, de joueur dans un effectif) : écarté, « N importés, M écartés (raisons) », rien en base ;
4. import mal formé (14 formes de match, 4 d'équipe, fichiers qui ne sont pas des sauvegardes) : les bons entrent, Historique et « Mes équipes » s'affichent ;
5. sauvegarde v1, v2 et archive faites depuis une vraie base : importées sans écart ni « Attention » ;
6. R3 : l'export JSON d'un match (téléchargement réel) est identique à `JSON.stringify(S, null, 2)` et se réimporte (aller-retour, second import ignoré, match seul mal formé écarté) ;
7. R22 : site servi en http, faux serveur de collecte, accord donné : seul le match avec auteur part, le match importé sans auteur reste visible.
Variable propre : aucune. Le contrôle 7 sert le site depuis le dossier de `KINBALL_HTML`.
Contrôle négatif : un dossier de site hors dépôt (liens vers le dépôt, sauf `index.html` et `kbcollect.js` pris dans les copies « d'avant » `kinball.C25.avant.html` et `kbcollect.C25.avant.js`) ; `KINBALL_HTML=<ce dossier>/index.html KINBALL_ONLY=C25 node tests/run.mjs` fait échouer 1, 2, 3, 4, 6 et 7 (le 5 est une non-régression et passe).
