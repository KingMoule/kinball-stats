## C27 : stockage de l'appareil (revue du 2026-10-09 · R2, R1)
Pannes **simulées** dans Chromium (jamais observées sur un iPad). Deux niveaux :
- `tests/local/kblocal.test.mjs`, cas E4 à E8 (façade seule, `KBLOCAL_ONLY=E4,E5,E6,E7,E8`) : connexion fermée sans événement (`db.close()`) ; événements `close` et `versionchange` (E5 est une garde de non-régression : ces deux événements étaient déjà oubliés avant C27) ; transaction refusée (`InvalidStateError`, `TransactionInactiveError`) une fois (rejouée) ou deux fois (rejet, puis écriture suivante réussie) ; écriture en cours quand la connexion se ferme (événement `close` puis avortement) ; lecture initiale refusée. Une seule réouverture et une seule émission par écriture rejouée.
- `scenarios/C27.mjs` (tablette et téléphone, 3 vérifications, page complète) :
  1. connexion morte en plein match : l'action suivante arrive en base sans recharger, badge ok, copie de secours retirée ;
  2. connexion morte pour de bon et transactions refusées pendant la panne : « Non enregistré », puis RÉESSAYER MAINTENANT enregistre sur une connexion neuve ;
